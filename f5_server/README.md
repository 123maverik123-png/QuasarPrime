# f5_server — синтез речи с клоном голоса

HTTP-сервис над **F5-TTS** (веса ESpeech `ESpeech-TTS-1_RL-V2`), API в стиле OpenAI:

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/health` | `{"ok": true}` когда модель загружена |
| `POST` | `/v1/audio/speech` | `{"input": "текст"}` → `audio/wav` (24 кГц) |

Запускается сам из корневого `launcher.py`:

```bash
python f5_server/f5_server.py \
    --ref voice/optimus_24k.wav \
    --ref-text voice/optimus.txt \
    --nfe 32 --port 8777
```

| Аргумент | Значение |
|---|---|
| `--ref` | WAV с образцом голоса (лучше 24 кГц, моно, 10–15 с чистой речи) |
| `--ref-text` | txt с **точной** расшифровкой образца — обязателен |
| `--nfe` | шаги инференса: `32` — качество, `16` — быстрее и чуть грязнее |
| `--port` | порт (по умолчанию 8777) |

## Что внутри

- `f5_tts` — сама модель (ставится из `requirements.txt`, веса тянет с HuggingFace
  при первом запуске, ~1.5 ГБ);
- `ruaccent` — расстановка ударений в русском тексте (это слышно: без неё модель
  «плавает» в ударениях);
- `soundfile` — запись WAV;
- патч `onnxruntime`: новые `tokenizers` не передают `token_type_ids`, а onnx-модель
  RUAccent их ждёт — подставляются нули.

## Зачем отдельный процесс

Модель занимает ~3.4 ГБ видеопамяти и грузится десятки секунд. Держать её в одном
процессе с ASR неудобно: падение синтеза не должно уносить весь сервер, а
перезапускать её отдельно дешевле. `quasard` общается с ней по HTTP
(`[tts] f5_url` в `config.toml`).

Если хочется изолировать зависимости (например, другой torch), создайте отдельное
окружение и укажите его в конфиге:

```toml
[launcher]
f5_python = "C:/QuasarPrime/.venv-f5/Scripts/python.exe"
```

## Первый запуск

Первый старт качает веса и прогревает модель (`Прогрев.`) — это может занять
1–3 минуты. `launcher.py` ждёт `/health` до `wait_timeout` секунд, так что просто
дайте ему время; в `logs/f5.log` будет видно прогресс.
