# Как снять трафик своей Яндекс Станции

Чтобы понять протокол и собрать свой бэкенд, нужно сначала посмотреть, как колонка общается с облаком Яндекса.
Станция ходит на серверы Яндекса по HTTPS, поэтому нужны три вещи: увести её домены на свой ПК (DNS), заставить
её ходить именно через твой DNS (иначе она может использовать свой) и расшифровать HTTPS (свой сертификат,
которому колонка доверяет).

> Делай это только со своей колонкой и в своей сети. Это интероп и исследование собственного устройства.

```
Яндекс Станция ──DNS "quasar.yandex.net?"──> роутер OpenWRT (192.168.2.1)
                                               dnsmasq: домены Яндекса → IP ПК
                                               nftables: весь DNS (53) → роутер
                                             ──HTTPS──> ПК (MITM-прокси, 443)
                                               лог в HAR → разбор протокола
```

## 1. DNS-перехват на роутере (OpenWRT)

Для каждого домена Яндекса отдаём IP своего ПК. Файл `/tmp/dnsmasq.cfg01411c.d/quasar.conf` (пути `/tmp` на
OpenWRT в tmpfs — после перезагрузки повторить):

```
address=/quasar.yandex.net/192.168.2.100
address=/uniproxy.alice.yandex.net/192.168.2.100
address=/oauth.yandex.ru/192.168.2.100
# ...остальные домены (полный список — KNOWN_HOSTS в alice_server/http_api.py)...
# IPv6 закрываем, чтобы по AAAA колонка не ушла к настоящему Яндексу:
address=/quasar.yandex.net/::
address=/uniproxy.alice.yandex.net/::
```

Применить: `/etc/init.d/dnsmasq restart`. Проверить: `nslookup uniproxy.alice.yandex.net 127.0.0.1`.

## 2. Принудительный DNS (nftables)

Колонка может ходить на свои DNS (8.8.8.8 и т.п.) мимо dnsmasq — заворачиваем весь DNS на роутер. Таблица
именно `ip` (на OpenWRT 25.x `inet` конфликтует):

```
nft add table ip dns_hijack
nft add chain ip dns_hijack prerouting '{ type nat hook prerouting priority -100; policy accept; }'
nft add rule ip dns_hijack prerouting udp dport 53 dnat to 192.168.2.1
nft add rule ip dns_hijack prerouting tcp dport 53 dnat to 192.168.2.1
```

Отключить: `nft delete table ip dns_hijack`.

## 3. HTTPS: свой сертификат, которому доверяет колонка

Чтобы расшифровать HTTPS, прокси предъявляет колонке сертификат на домены Яндекса. Колонка примет его только
если доверяет удостоверяющему центру (CA), которым он подписан.

### Как это исторически обходили

Старые прошивки станции доверяют промежуточному CA eMudhra, который входил в системное хранилище Android. У
этого CA утёк приватный ключ, поэтому им можно подписать сертификат на любой домен, и колонка его примет без
установки чего-либо на устройство. Исторически перехват трафика станции делали именно так — сертификатом,
подписанным скомпрометированным ключом eMudhra.

**Это ненадёжно и небезопасно.** Способ держится на утёкшем ключе публичного CA: как только такой CA отзывают
или прошивка перестаёт ему доверять, всё ломается. И это не локальная история — тем же ключом можно подделать
HTTPS любого сайта (банк, почта) на чужом устройстве, так что сам факт его существования опасен для посторонних
людей, а не только для Яндекса. Поэтому ключ и ссылки на него в этот проект не входят; ищи по запросу «eQuasar»
/ «eMudhra leaked», если понимаешь риски.

### Рекомендуемый способ — свой CA на своём устройстве

Надёжнее и безопаснее: сгенерировать собственный CA и доверить его только своей колонке. Он не даёт власти над
чужими устройствами и не отвалится при отзыве чужого CA.

1. Сгенерируй свой CA и сертификат на все домены: `python tools/gen_certs.py --ip <IP ПК>` (создаёт
   `certs/ca.crt`, `certs/server.crt`, `certs/server.key`).
2. Установи `certs/ca.crt` в хранилище доверенных сертификатов колонки. На Android-прошивке станции для этого
   нужен root или доступ по adb — это самая трудоёмкая часть и зависит от прошивки.
3. Укажи эти `server.crt`/`server.key` в `config.toml` — сервер сам поднимет HTTPS на 443.

> Не используй для этого чужие или утёкшие ключи публичных удостоверяющих центров: это компрометация TLS для
> всех, а не только для твоего устройства. Только свой CA на своём устройстве.

## 4. Снятие трафика в HAR

Пока точного дампа ещё нет, прокси работает в режиме «прозрачного» MITM: принимает HTTPS от колонки, пишет
запрос и ответ в HAR и проксирует на настоящий сервер Яндекса. Подойдёт любой HTTPS MITM-прокси, умеющий
сохранять HAR (например, mitmproxy: `mitmproxy --mode reverse` с подстановкой Host, экспорт в HAR). WebSocket
`uniproxy.alice.yandex.net/uni.ws` прокси пересылает на настоящий Яндекс и логирует кадры.

## 5. Из HAR в свой бэкенд

- `python tools/import_har.py capture.har` вытаскивает из дампа ответы `get_sync_info`, `device_list`,
  `user_details` и образцы голоса.
- Дальше запускается `alice_server`: он отвечает колонке сам (активация, конфигурация), а голос обрабатывает
  своими моделями. Проверка без колонки — `tools/station_sim.py` и `tools/activation_sim.py`.

HAR-файл содержит твои токены Яндекса, идентификаторы устройств и Wi-Fi — не выкладывай его.
