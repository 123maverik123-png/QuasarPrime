# Пауза: кнопка в панели и кольцо на Станции

Разбор по логам 28.10.2026 (`logs/serve.log` моста и `/data/quasar/daemons_logs/maind.log`
Станции Lite 2, `L01Q9S4000AN4V`).

## Что было не так

1. **Кнопка паузы в панели не ставила паузу на колонке.** Мост по умолчанию
   (`playback.pause_command = false`) только запоминал позицию: Glagol-команда
   не отправлялась. Станция продолжала играть из своего буфера (она качает
   поток вперёд на минуты), а панель уже считала себя на паузе. При
   «продолжай» мост переподключал поток с зафиксированной секунды — отсюда
   ощущение «колонка начала играть с места паузы».

2. **Пауза кольцом не останавливала тайминг в панели.** Кольцо на колонке —
   это локальное `playback_toggle_play_pause` → `audio_stop` →
   `player_finish` и стирание сессии проигрывателя:

   ```
   [buttons_actions.cpp:298] Toggle play/pause
   [directive_sequencer.cpp:663] addDirectives [(xxf2e2bf59)playback_toggle_play_pause...]
   [playback_control_capability.cpp:545] Pausing current playback
   [media] Music session changed to player_finish: reason audio_play.Text.Hardware.Click...
   [media] Erase audio player session by playerId: (xx6e07d827) AUDIO_PLAY
   ```

   При этом **HTTP-поток не закрывается** — байты просто перестают
   забираться. По `bytes_sent`/`stalled_s` паузу не отличить от нормального
   воспроизведения из буфера (в логе Станция забирает поток рывками и молчит
   в сокете по 10–13 с). Поэтому статус оставался `streaming`, а панель
   продолжала считать время.

3. Мягкой паузы для `audio_play` у прошивки нет: и кольцо, и Glagol
   `{"command":"stop"}` дают один и тот же `audio_stop` с удалением сессии
   (`stop` → `playback_pause.Glagol` → `audio_stop`). Сохранить позицию можно
   только на своей стороне — что мост и делает.

## Что сделано

* `playback.pause_command = true` по умолчанию: `/api/pause` запоминает
  позицию и отправляет Станции `stop`, то есть музыка реально замолкает.
* Позиция паузы берётся из `playerState.progress` Станции, а не из наших
  часов: Станция раз в секунду присылает по Glagol `state.playing` и
  `playerState.progress` (позиция внутри отданного потока).
* `StreamSession.apply_station_state()`: `playing=false` дольше 1.5 с →
  `state=paused`, `paused_by=station`, позиция фиксируется по последнему
  `progress`. Если Станция снова заиграла сама (договорила и продолжила) —
  пауза снимается без наших команд.
* Позиция для панели (`played_ms`) теперь = `start_ms + progress`, пока
  Станция играет. Это точнее прежней оценки по часам: в логе при `elapsed=17 c`
  звук был на 11.6 c — ровно столько Станция буферизует на старте.
* `resume_offset` считается из позиции (`position_byte()`), а не из
  `bytes_sent`: иначе без `Range` от Станции трек прыгал бы вперёд на минуты.
* Позиции не верим, пока Станция ни разу не играла этот поток: сразу после
  `audio_play` она ещё присылает `playerState` прошлого трека (та же
  длительность — «наш»), и панель показывала чужую секунду.
* Панель: опрос раз в 2 с вместо 3, бейдж «пауза на колонке» при
  `paused_by=station`.

```
17:51:23 Продолжение принято: Станция снова читает поток

```

Та же последовательность, но паузу поставила Станция (`stop` в обход сессии,
как это делает кольцо): статус сам перешёл в `paused/paused_by=station` с
позицией `31429 мс`, «продолжай» поднял трек с 31.4 с.

## Ограничения

* «Продолжай» — это переподключение потока: `stop` + `audio_play(offset_ms)`
  с новым url, около секунды (в тестах 1 попытка из 2).
* Сама Станция после паузы показывает позицию внутри остатка, а панель —
  абсолютную.
* Если Станция успела скачать поток до конца, пауза кольцом выглядит как
  `finished` (продолжать нечем) — трек начнётся заново.
